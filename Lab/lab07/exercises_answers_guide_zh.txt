Exercise 1 (Task 1) - 答案与详细推理指南
========================================

【Scenario 1】 (参数: a1=1步长, a3=0仅写)
1. 观察到的命中率：0.5 (50%)
   推理：Block Size 是 8 bytes，一个数组元素(word)是 4 bytes。所以一个 Block 正好能装 2 个元素。
   步长 a1=1 意味着按顺序连续访问。访问第1个元素时必定 Miss，并将包含第1和第2个元素的 Block 载入缓存。紧接着访问第2个元素时，它已经在同一个 Block 里了，所以 Hit。
   规律是：Miss, Hit, Miss, Hit... 因此命中率为 50%。

2. 增加 Rep Count：命中率不变，依然是 0.5 (50%)。
   推理：Cache 的总容量 = 4 Blocks * 8 bytes = 32 bytes。而我们的数组大小是 256 bytes。
   当第一轮循环结束时，Cache 里只保留了数组最后 32 个字节的数据。当开始第二轮（Rep Count）回到数组开头时，开头的数据早已经被驱逐了（这叫 Capacity Miss 容量未命中）。因此，每一轮的情况都和第一轮一模一样。

3. 提高命中率的程序参数：减小 `a0` (Array Size) 到 32 及以下。
   推理：只要数组大小 <= Cache 总容量 (32 bytes)，整个数组跑完一遍后就不会被驱逐。第二轮及以后再访问时，命中率将达到 100%。

【Scenario 2】 (参数: a1=2步长, a3=0仅写)
1. 内存访问次数：1 次。
   推理：a3=0 代表只执行写（store / sw）操作，没有读操作。

2. 规律与原因：规律是全部 Miss (Miss, Miss, Miss...)。
   推理：现在的步长是 2 个 word，也就是 8 字节。而 Block Size 刚好也是 8 字节。
   这意味着每次访问，都会精准跨过当前 Block 的覆盖范围，落入下一个全新的物理 Block。之前载入的数据根本得不到重用（破坏了空间局部性）。

3. 命中率推算：0%。
   推理：每次都是全新的地址，全部是 Compulsory Miss。

【Scenario 3】 (参数: a1=1步长, a3=1读和写)
1. 内存访问次数：2 次。
   推理：a3=1 要求先加载(lw)数组元素，加一后，再存回(sw)相同地址。

2. 规律：Miss, Hit, Hit, Hit。
   推理：
   - lw 元素1：Miss（顺便把元素1和元素2所在的Block加载入缓存）
   - sw 元素1：Hit（因为地址相同，刚刚已经被 lw 载入缓存了，时间局部性）
   - lw 元素2：Hit（因为和元素1在同一个Block，空间局部性）
   - sw 元素2：Hit（时间局部性）

3. 命中率推算：75% (0.75)。(4次操作中命中3次)。

4. 增加 Rep Count：命中率不变，依然是 75%。
   推理：原因和 Scenario 1 的第2问完全相同（Capacity Miss），缓存太小装不下 256 bytes 的大数组。

5. 提高命中率的硬件参数：
   - 增加 `Number of Blocks` 到至少 32（使得总容量达到 256 bytes，消除 Capacity Miss）。
   - 或者增加 `Block Size`（比如增大到 16 bytes，这样一个 Block 能装 4 个元素，初始的 Miss 比例就会降低）。

--- Checkoff Questions ---
C1: Spatial Locality (空间局部性)。
C2: 步长增加导致跨度(stride)等于块大小，每次访问都跨越到新块，完全摧毁了空间局部性红利。
C3: 读操作可能会 Miss，但会将数据带入缓存；随后的写操作针对同一地址，享受了极高的时间局部性，必定 Hit。

Exercise 2 (Task 2) - 答案与详细推理指南
========================================

1. 最快的顺序：`ikj` 和 `kij` (即把 `j` 放在最内层循环的顺序)。
   推理：C语言中，`C[i][j]` += `A[i][k]` * `B[k][j]`。
   如果最内层变量是 `j`，那么随着 `j` 的递增：
   - `C[i][j]` 和 `B[k][j]` 都是同行内连续访问的，步长为1，具备完美的空间局部性！
   - `A[i][k]` 中没有 `j`，这意味着在最内层循环中它是一个常数，甚至可以直接被放在 CPU 寄存器里，连内存都不用读！这是极致的优化。

2. 最慢的顺序：`jki` 和 `kji` (即把 `i` 放在最内层循环的顺序)。
   推理：如果最内层是 `i`：
   - `C[i][j]` 和 `A[i][k]` 随着 `i` 的改变，都是按列跨行访问的。每次跨越整个矩阵的宽度 N，跳跃距离巨大，必定疯狂触发 Cache Miss。

--- Checkoff Questions ---
C1: 跨步访问（Stride N）极其糟糕，因为每次访问都浪费了载入到 Cache Block 中的其余数据，导致缓存失效（Thrashing）；连续访问（Stride 1）最佳，能充分利用 Block 的容量。
C2: Row-Major（行优先）。
C3: 写代码时要尽量让最内层循环遍历最右侧的数组索引。

Exercise 3 (Task 3) - 答案与详细推理指南
========================================

Part 1: 
C1: 当 N 较小时，两者的矩阵都能完整放进 L1 缓存，耗时差距不大。当 N 变得很大时，Naive 版本耗时呈爆炸性增长（因为严重的缓存颠簸），而 Blocking 版本耗时增长平缓，两者差距如鸿沟般拉开。
C2: 在 N 非常小的时候，不需要分块也不会产生 Cache Miss，此时 Blocking 因为嵌套了复杂的 4 层循环，增加了额外的计算开销和分支判断，反而可能比简单的 Naive 循环更慢。

Part 2:
C3: 性能【不是】单调提升的！当 blocksize 逐渐变大时，性能一开始会提升（因为循环控制开销减少）。但当 `blocksize * blocksize` 的这个子块本身的体积**超出了 CPU L1 缓存的容量**时，在处理这一个子块的过程中就会发生互相驱逐（Capacity Miss/Conflict Miss），此时性能会再次大幅度下滑。因此存在一个能刚好塞满 L1 缓存的最佳 Sweet Spot。
