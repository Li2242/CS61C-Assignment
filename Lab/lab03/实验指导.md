# Lab03 实验指导（RISC-V 汇编）

这份指导按你目录里的文件组织，目标是帮助你按顺序完成并自检：

- `ex1.s`：斐波那契循环与基础指令
- `ex2.c` / `ex2.s`：从 C 翻译到汇编
- `factorial.s`：递归与栈帧
- `list_map.s`：链表递归 + 函数指针调用
- `cc_test.s`：Calling Convention（调用约定）修复

## 1) 做题顺序建议

推荐顺序：`ex1 -> ex2 -> cc_test -> factorial -> list_map`

原因：

1. `ex1/ex2` 先熟悉寄存器与控制流。
2. `cc_test` 先把调用约定彻底搞懂，后面递归会轻松很多。
3. `factorial/list_map` 都依赖正确栈管理和寄存器保存。

## 2) 快速复习：本实验最常用规则

### 2.1 参数与返回值

- 参数寄存器：`a0-a7`
- 返回值寄存器：`a0`（必要时 `a1`）

### 2.2 调用者保存 / 被调用者保存

- 调用者保存（caller-saved）：`t0-t6`, `a0-a7`, `ra`
- 被调用者保存（callee-saved）：`s0-s11`

一句话判断：

- 你是“函数调用别人”的一方，若还要用 `t` 寄存器旧值，调用前自己压栈。
- 你是“被调用函数”，若修改了 `s` 寄存器，必须在 prologue/epilogue 成对保存恢复。

### 2.3 栈帧基本模板

```asm
# prologue
addi sp, sp, -N
sw ra, offset(sp)
sw s0, offset(sp)

# ... function body ...

# epilogue
lw s0, offset(sp)
lw ra, offset(sp)
addi sp, sp, N
jr ra
```

## 3) 各文件怎么做

## `ex1.s`（斐波那契）

你这题核心是循环状态更新：

- `t0` / `t1` 维护相邻两项
- `t3` 维护剩余迭代次数
- 每轮：算新值 -> 旧值前移 -> 计数减一

检查点：

- 循环出口条件是否正确（`beq t3, x0, finish`）
- 更新顺序是否会覆盖还没用的值

---

## `ex2.c` -> `ex2.s`（C 到汇编翻译）

### 关键映射

- `source[k]` / `dest[k]`：索引要乘 4（`slli idx, idx, 2`）
- `for (k=0; source[k]!=0; k++)`：先加载元素，再判断是否 0
- `fun(x) = -x * (x + 1)`：可以用
  - `addi t0, a0, 1`
  - `sub t1, x0, a0`
  - `mul a0, t0, t1`

### 易错点

1. `jal fun` 后，调用者临时寄存器可能被覆盖。
2. 若循环变量放在 `t0`，调用前后要考虑是否保留。
3. `main` 若用了 `s` 寄存器，需在 prologue/epilogue 成对处理。

---

## `cc_test.s`（调用约定专项）

这个文件的目标不是“算对就行”，而是“严格无 CC 违规”。

### `simple_fn`

- 保证返回 `a0 = 1` 即可
- 不要做无意义读写导致依赖未定义值

### `naive_pow`

- 使用了 `s0`，必须保存/恢复 `s0`
- 如果函数里调用别人还要考虑 `ra`，本函数不再调用其他函数时可不额外保存 `ra`

### `inc_arr`

- 调用了 `helper_fn`，调用点要考虑 caller-saved
- 特别是循环计数（若放在 `t0`）需要在调用前后保护
- 若用了 `s0/s1`，也要在函数出入口保存恢复

### `helper_fn`

- 不要用 `s` 寄存器做临时值（或用了就成对保存恢复）
- 最简单是全用 `t` 寄存器完成加一写回

## `factorial.s`（递归）

推荐思路：

1. **基例**：`n == 0` 或 `n == 1` 返回 1。
2. **递归步**：先保存当前 `n`，调用 `factorial(n-1)`，返回后乘回原 `n`。

必须处理：

- 递归函数一定要保存 `ra`（因为会 `jal` 自己）
- 若要跨调用保留当前 `n`，可压栈或放 `s` 寄存器并保存恢复

可用骨架：

```asm
factorial:
    addi sp, sp, -8
    sw ra, 4(sp)
    sw a0, 0(sp)      # 保存 n

    li t0, 1
    ble a0, t0, base

    addi a0, a0, -1
    jal ra, factorial
    lw t1, 0(sp)      # 取回原 n
    mul a0, a0, t1
    j done

base:
    li a0, 1

done:
    lw ra, 4(sp)
    addi sp, sp, 8
    jr ra
```

## `list_map.s`（递归链表 map）

结构体布局（每个节点 8 字节）：

- `0(a0)`：`value`
- `4(a0)`：`next` 指针

`map(head, f)` 逻辑：

1. 若 `head == NULL`，直接返回。
2. 读当前节点值到 `a0`，调用函数指针 `f`。
3. 把返回值写回当前节点。
4. 取 `next` 作为新的 `a0`，函数地址继续放在 `a1`，递归调用 `map`。

关键点：

- 函数指针调用不是 `jal label`，而是 `jalr`。
- 递归函数里修改了哪些 `s` 寄存器，就要保存恢复。
- `main` 里要先把 `square` 的地址放入 `a1`（比如 `la a1, square`）。

## 4) 自检清单（每题提交前过一遍）

- 能跑出预期功能结果（数值正确）
- 没有明显越界/空指针访问
- 所有被修改的 `s` 寄存器都在函数内成对保存恢复
- 递归函数正确保存 `ra`
- 调用点前后对关键 caller-saved 寄存器做了保护

---

## 5) 调试建议

- 单步看 `sp`：确保每次进出函数栈高度对得上。
- 观察 `ra`：递归返回错层通常是 `ra` 没存好。
- 先最小化验证：先让基例正确，再加递归步。
- 对循环代码，先打印/观察前 2~3 轮寄存器变化，快速定位更新顺序问题。
