## Experiment Overview & Goals

本实验围绕 RISC-V 汇编中的两类核心能力：

1. 将离散函数映射问题转化为内存访问与地址计算。
2. 在链表 + 数组 + 函数指针 + 递归场景下，严格遵守 calling convention 进行调试与修复。

你将完成两部分：

- `discrete_fn.s`：实现函数 `f`。
- `megalistmanips.s`：修复函数 `map`，使其正确遍历并修改链表中每个数组元素。

完成后你应能做到：

- 从规格推导寄存器级实现，而不是“试错式拼指令”。
- 清晰区分 caller-saved / callee-saved 的责任边界。
- 在递归汇编中稳定管理参数、返回地址、栈帧与中间状态。

## Task 1: 在 `discrete_fn.s` 完成 `f`

### Specification

函数输入输出约定：

- 输入：
  - `a0`：待求值自变量 `x`（测试范围 `-3..3`）。
  - `a1`：`output` 数组首地址。
- 输出：
  - `a0`：函数返回值。

行为要求：

- 对所有测试输入，返回与值表一致的结果。
- 函数结尾正确返回到调用点。

### Thinking Guide

先回答源码注释里的关键问题：**为什么 `a1`（output 地址）会传给 `f`？**

这通常意味着：

- 题目希望你使用“查表法”实现离散函数；
- 而不是写 7 个分支逐个硬编码。

建议推理链：

1. 输入区间连续：`-3,-2,-1,0,1,2,3`。
2. 输出表中元素按同一顺序存放。
3. 先把负数区间平移成从 0 开始的下标。
4. 把下标转换成字节偏移（word = 4 bytes）。
5. 从 `a1 + offset` 读取目标值返回。

### Hints

- 先做“数学映射”，再做“地址映射”。
- `lw` 偏移单位是字节，不是元素编号。
- 保持实现短小、可读、数据驱动。
- 临时寄存器跨函数调用不保证保留（本题虽不复杂，但习惯要对）。

### Implementation Steps

1. 进入 `f`，明确最终必须让 `a0` 装载返回值。
2. 将输入 `x` 映射到合法数组下标范围。
3. 将下标扩展为字节偏移。
4. 与 `a1` 相加得到目标地址。
5. `lw` 取值到 `a0`。
6. `jr ra` 返回。
7. 运行并逐行核对打印结果中的“should be”和“it is”。

## Task 2: 在 `megalistmanips.s` 修复 `map`

### Specification

`map` 语义：

- 对链表每个节点的数组执行逐元素变换。
- 变换函数由函数指针参数提供。
- 结果原地写回数组。

函数参数：

- `a0`：当前节点地址（可为空）。
- `a1`：函数指针（本题传入 `mystery`）。

节点布局（每节点 12 字节）：

- `0(a0)`：数组首地址。
- `4(a0)`：数组长度。
- `8(a0)`：下一节点地址。

正确行为：

- 空节点立即返回。
- 当前节点数组全部处理后，递归处理下一节点。
- 严格遵守 calling convention。

### Thinking Guide

这题本质是“结构化调试题”。你要先从高层语义倒推汇编，而不是盯着错误代码逐条修补。

建议先写出伪代码模型（仅思维，不抄答案）：

- `if node == NULL: return`
- `for i in [0, size): arr[i] = f(arr[i])`
- `map(node->next, f)`

然后逐项对照汇编：

- 哪个寄存器保存 `node`、`fptr`、`i`、`arr`、`size`？
- 哪些值要跨 `jalr` 与递归调用存活？
- 每次内存访问是不是都基于正确“基地址 + 正确偏移”？

### Hints

- `jalr` 调用后，caller-saved（如 `t*`, `a*`）都可能被破坏。
- 索引如果按“元素数”增长，访问时要转换为字节偏移。
- 取 `next` 指针应来自当前节点内存字段，不是标签地址拼接。
- 递归前要重新装载 `a0/a1` 参数，不能假设仍是旧值。
- base case 必须在任何解引用之前检查。

### Implementation Steps

1. 检查并修正 prologue：保存你实际使用的 `s*` 与 `ra`。
2. 放置 base case：若 `a0 == 0`，直接走返回路径。
3. 从当前节点读取 `arr` 与 `size`。
4. 初始化循环变量，从第 0 个元素开始。
5. 在循环体中完成：取元素 -> 调函数 -> 写回元素。
6. 完成循环终止条件，确保“恰好处理 size 个元素”。
7. 读取 `next`，恢复函数指针参数，设置递归调用参数。
8. 递归调用 `map`。
9. epilogue 对称恢复寄存器与栈指针，再返回。

## Testing、Running、Debugging

### 1) `discrete_fn.s` 验证

- 目标：7 条输出全部与期望一致。
- 若仅部分点错误：优先检查“输入平移量”和“下标缩放”。

### 2) `megalistmanips.s` 验证

- 程序会打印 `Lists before` 与 `Lists after`。
- 你应检查 after 中每个数是否满足 `x*x+x` 变换。

### 3) 高效调试路径

- 先验证第一节点第一元素。
- 再验证第一节点完整数组。
- 再验证跨节点递归。

### 4) 典型现象到根因映射

- **只改了第一个元素**：循环增量/终止条件错误。
- **只改了第一节点**：`next` 参数准备错误。
- **输出随机/跳变**：被调用函数后寄存器被覆写。
- **崩溃**：地址计算错误或栈帧损坏。

## Common Mistakes & Fixes

### Mistake A：元素索引当字节偏移使用

- 现象：访问错位、数值异常。
- 修复：访问前做 *元素到字节* 的转换。

### Mistake B：把节点地址当数组地址

- 现象：覆盖结构字段，程序很快异常。
- 修复：先从节点字段取出数组指针，再做下标访问。

### Mistake C：调用后继续依赖 `t*`/`a*` 旧值

- 现象：循环变量突然错乱。
- 修复：跨调用长期存活数据放 `s*` 或每轮重算。

### Mistake D：递归参数未正确重建

- 现象：无限递归、空指针崩溃、或只处理一层。
- 修复：递归前显式写明 `a0 = next`, `a1 = fptr`。

### Mistake E：栈帧前后不对称

- 现象：`jr ra` 后跳转异常。
- 修复：保存/恢复集合与栈空间大小必须完全匹配。

## Key Takeaways

- 汇编实现先看“数据布局 + 函数契约”，再写指令。
- calling convention 是硬约束，不是风格建议。
- 递归题调试要分层：本层循环正确 -> 参数重建正确 -> 递归正确。
- 先修第一处偏差，能显著缩短总调试时间。
