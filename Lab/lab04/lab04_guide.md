## 📚 Prerequisite Knowledge

在开始之前，请确保你已经掌握了以下 Lecture 知识：
- **RISC-V Registers**: 了解 `a0-a7`（参数/返回值）、`t0-t6`（临时寄存器）、`s0-s11`（保存寄存器）、`ra`（返回地址）、`sp`（栈指针）。
- **Memory Addressing**: 理解字节编址（Byte Addressing）。在 RISC-V 中，一个 Word（字）是 4 个字节。访问数组的下一个元素需要将地址加上 4（即 `offset * 4`）。
- **Calling Convention**:
  - **Caller-saved** (`t` 寄存器, `a` 寄存器, `ra`)：如果你在调用子函数后还需要使用这些寄存器的值，你**必须**在调用前将它们压入栈（Stack）中，并在调用后恢复。
  - **Callee-saved** (`s` 寄存器, `sp`)：如果你要在函数内部使用这些寄存器，你**必须**在函数开头将它们的旧值压栈，并在函数返回前（`jr ra`）将它们恢复为原样。

## 📝 Task 1: Discrete Function (`discrete_fn.s`)

### Specification
你需要实现一个汇编函数 `f`，该函数根据输入的 $x$ 值（通过 `a0` 传入，范围是 $[-3, 3]$），返回对应的 $y$ 值。
我们不是用复杂的数学公式来计算 $y$，而是**查表**。在 `main` 函数中，我们已经为你准备好了一个包含 7 个整数的数组 `output`，它的首地址通过 `a1` 传入 `f`。你需要读取数组中对应的元素并将其放入 `a0` 作为返回值。

### Thinking Guide
1. **输入与索引映射**：
   输入的 $x$ 是 $[-3, 3]$。但在 C/汇编中，数组的索引是从 $0$ 开始的 $[0, 6]$。
   *思考*：如果 $x = -3$，它应该对应数组的第 $0$ 个元素。如果 $x = -2$，对应第 $1$ 个。你需要对 `a0` 做什么数学运算来得到实际的数组索引？
2. **字节偏移量计算**：
   假设你计算出的实际索引是 `index`。RISC-V 内存是按字节寻址的，而我们的数组是 Word（4字节）数组。
   *思考*：如何将 `index` 转换为字节偏移量 `offset`？（提示：乘以 4，或者使用左移指令 `slli`）。
3. **内存加载**：
   你现在有了数组的基地址（在 `a1` 中）和字节偏移量（你刚刚算出来的）。
   *思考*：如何将这两者结合起来计算出目标元素的绝对地址？然后你需要使用哪条指令（`lw`, `lh`, `lb`？）将数据从内存加载到寄存器中？

### Hints
- 使用 `addi` 指令来完成加法映射。
- 使用 `slli t0, reg, 2` 是将寄存器乘以 4 的高效方法。
- RISC-V 的 `lw dst, offset(base)` 指令要求 offset 必须是常数（立即数）。如果你计算出的偏移量在一个寄存器里，你需要先使用 `add` 将基地址和偏移量相加，然后再使用 `lw dst, 0(new_base)`。

### Implementation Steps
1. 在 `discrete_fn.s` 中找到 `f:` 标签。
2. 将输入 `a0` 转换为从 0 开始的逻辑索引。
3. 将逻辑索引乘以 4 得到字节偏移量。
4. 将字节偏移量加到数组基地址 `a1` 上。
5. 解引用该新地址，将值加载回 `a0`。
6. 使用 `jr ra` 返回。

## 📝 Task 2: Megalist Manipulation (`megalistmanips.s`)

### Specification
在这个任务中，你需要修复 `map` 函数中的 Calling Convention Bug。
`map` 函数的作用是：遍历一个链表，每个链表节点包含一个数组。`map` 接收一个函数指针，并将该函数应用到链表节点数组中的每一个元素上。
目前的 `map` 函数逻辑上看起来是对的，但它**完全没有遵守** Calling Convention。当你运行它时，它会崩溃或者进入死循环。你的任务是添加适当的 Prologue（序言：保存寄存器）和 Epilogue（结语：恢复寄存器）。

### Thinking Guide
仔细分析 `map` 函数的代码。`map` 在其内部调用了其他函数（它调用了传入的函数指针）。因此，`map` 既是 Callee（被 `main` 调用），又是 Caller（调用其他函数）。

**第一步：识别 Callee-saved 的违规**
- `map` 函数在执行过程中使用了哪些 `s` 寄存器？（仔细看代码，它用了 `s0`, `s1`, `s2` 等等吗？）
- 如果 `map` 修改了这些 `s` 寄存器，它必须在函数的开头将它们压栈，在结尾恢复。
- **别忘了 `ra`**！因为 `map` 内部使用了 `jal` / `jalr` 调用其他函数，它自己的 `ra`（返回 `main` 的地址）会被覆盖。`ra` 也必须被压栈保护！

**第二步：识别 Caller-saved 的违规**
- 在 `map` 内部循环调用函数指针之前，`map` 可能会把一些重要的状态放在 `t` 寄存器或 `a` 寄存器中。
- *思考*：当 `map` 调用那个未知的函数指针时，那个函数有可能会修改所有的 `t` 寄存器和 `a` 寄存器。如果 `map` 在调用之后还需要用到某个 `t` 寄存器的值（比如当前的数组索引，或者循环计数器），它能信任这个 `t` 寄存器没有被改变吗？**绝对不能！**
- 解决方法：你可以选择在调用前后把 `t` 寄存器压栈/出栈；**或者更聪明的做法是**：不要把跨越函数调用仍需保留的变量存放在 `t` 寄存器中，而是将它们转移到 `s` 寄存器中（因为根据约定，被调用的函数必须保证 `s` 寄存器不变）。当然，如果你把它们放到了 `s` 寄存器，请参考第一步，确保你在 `map` 的开头/结尾正确保存了这些 `s` 寄存器。

### Hints
- **Stack 空间分配**：在函数开头，使用 `addi sp, sp, -N` 分配空间，然后使用 `sw` 保存寄存器。在结尾，使用 `lw` 恢复，然后 `addi sp, sp, N` 释放空间。注意 `N` 必须是 4 的倍数（推荐 16 的倍数以对齐）。
- **仔细追踪 `a0` 和 `a1`**：在调用函数指针时，你需要将正确的参数放入 `a0`。这可能会覆盖掉 `map` 自己原本收到的参数（链表头指针）。确保你在覆盖前将重要数据备份到了安全的寄存器（`s` 系列）中。

### Implementation Steps
1. 阅读 `map` 函数，列出它内部使用到的所有 `s` 寄存器。
2. 在 `map` 标签后，立即编写 Prologue：向下移动栈指针 `sp`，使用 `sw` 保存这些 `s` 寄存器以及 `ra`。
3. 检查循环内部：在 `jalr`（调用传入的函数）前后，是否有任何 `t` 或 `a` 寄存器的值需要在调用后继续使用？
4. 如果有，将这些变量的使用替换为 `s` 寄存器。
5. 在 `map` 的所有返回点（`jr ra` 之前），编写 Epilogue：使用 `lw` 从栈中恢复保存的寄存器，并向上移动 `sp` 释放栈空间。

## ⚠️ Common Mistakes & Fixes

1. **栈指针忘记恢复**：在函数退出前，分配了多少 `sp`，就必须加回多少 `sp`。否则会导致上层函数的栈错乱。
2. **Push/Pop 顺序错误**：栈可以随意存取（只要 offset 正确），但必须保证你 `sw` 到哪个 offset，`lw` 时也要从同一个 offset 读取。
3. **过度保存 Caller-saved**：有些同学会在每次 `jal` 前把所有 `t0-t6` 全存一遍。这虽然不会报错，但极其低效。请只保存那些**在调用后仍需要用到**的寄存器，或者干脆改用 `s` 寄存器。

## 💡 Key Takeaways

- 内存是一维的连续字节序列。高维数组或复杂数据结构在底层都必须被拍平成地址和偏移量的计算。
- **Calling Convention 不是建议，是绝对的法则。** 在复杂的程序（尤其是有外部库或编译型代码）中，任何对寄存器约定的违反都会导致极其隐蔽且难以调试的 Bug。
